# cursor-switch 设计方案

我要做的是一个本机网关：让 Cursor 使用我自己配置的第三方模型。模型地址、密钥和协议由我在桌面里配置。请求留在本机完成编排，再发给我选择的上游。

Cursor 通过本地 HTTPS 代理进入我的服务。Agent 请求由我编译后发给上游模型。Tab 和我没有实现的 Cursor 接口，我原样转给 Cursor 官方。

## 我要做的范围

- 本地 CA、只接管 Cursor 域名的 HTTPS 代理、本地 token 判断、未知 RPC 转发官方、出站代理。
- Agent 上行与 SSE 下行、`request_id` 通道。连通性探测我固定返回已连接，避免慢请求被 Cursor 取消。
- 会话运行时：一个会话只有一个当前 run。我处理忽略、插入和打断，做上下文压缩和前缀稳定，支持 agent、ask、plan、debug、multitask、subagent。输入包含 rules、skills、MCP、环境、图片和 blob，并把 Cursor 里的模型名映射到我配置的模型。
- 工具：文件与终端、交互编排、MCP、网页搜索、本地代码搜索、生图，以及流式参数、执行、交互和结果门控。
- 检查点、从 Cursor 会话状态恢复、SQLite。
- 模型目录、账号外观、知识库、提交信息、Blob 与上下文同步、用量与调用记录。遥测接口我只回空成功，不采集、不上报。
- 桌面：用量图表、模型配置、批量修改、拉取模型列表、连通性测试、调用记录、计价、观测详细程度、提交信息所用模型、语言、主题、开关机、存储清理、主窗口、托盘、系统终端、启动失败提示。桌面由我拉起本地服务。
- 上游协议：OpenAI Chat Completions、OpenAI Responses、Anthropic Messages。我把它们收成同一种流式事件和用量，支持自定义 Headers 与额外参数。可重试失败我最多重试 8 次，间隔 5 秒，并保存请求与响应。
- 协议开发工具：我需要能从 Cursor 客户端产物提取 protobuf 服务、消息和字段，并生成协议定义；还需要独立的抓包调试服务，把 Cursor 请求解码后存起来，用网页对照真实流量。这两套工具只给开发联调用，不进入用户桌面。

我明确不做这些：

- Tab 补全协议。Tab 我转给 Cursor 官方，自己不实现补全服务，也不接入任何第三方公益补全地址。
- 旧版配置导入、插件管理页、自动更新。
- 对外的 OpenAI 或 Anthropic 兼容接口。
- 广告，以及 Grok、Codex、Antigravity 登录插件。

## 我采用的进程与路径

我把桌面和本地服务分成两个进程。桌面负责窗口，并拉起或连接服务。服务开两个端口：一个给 Cursor 代理，一个只监听回环地址，给桌面控制面使用。

```text
Node.js 桌面（Electron 窗口 + Vite 界面）
    │ 本机 HTTP
    ▼
FastAPI 控制面
    │
    ▼
应用服务（模型、设置、用量、知识库）
    │
    ├── Cursor 适配层：代理、Connect、编译、工具线路、官方回退
    ├── 会话运行时：Run 状态机、工具循环、压缩、检查点
    └── 上游策略：Chat、Responses、Anthropic
            │
            ▼
         SQLite
```

Cursor 进入后，我按下面四步处理：

1. TLS 代理按 Host 和路径判断。Tab 和我未实现的 RPC 转到官方。Agent、模型目录、账号外观和知识库留在本机。
2. `BidiAppend` 按 `request_id` 排序后，我把它编译成忽略、插入或打断。
3. 一个会话我只保留一个当前 run。运行时向所选上游要流，再把文本、工具调用和结果编回 Cursor 下行。
4. 检查点在 run 收尾前写完。桌面从 SQLite 读用量、调用记录和配置，不订阅 Cursor 内部事件。

模型配置我保存协议类型、地址、密钥、显示名、上下文窗口和额外参数。连通性测试走同一条上游策略，不进入会话。

## 我选择的框架

| 我的选择 | 理由 |
| --- | --- |
| Python 3.12 | 我需要稳定的 asyncio 任务组和当前类型语法，运行时只依赖这一版。 |
| FastAPI、Uvicorn | Cursor 上行是 HTTP，下行是长连接 SSE，我的控制台也是 HTTP。FastAPI 能同时承载并直接返回流。Django 的同步应用模型不适合这条长连接。 |
| httpx | 三种上游协议我都要读 SSE，并且要走我配置的出站代理。一个异步客户端同时覆盖这两点。 |
| 官方 protobuf 运行时 | 我用 Cursor 的 `.proto` 生成 Python 消息类。手写兼容层会在字段增减时漂移。生成代码只作传输对象，不进入我的运行时核心。 |
| SQLAlchemy 2、aiosqlite | 会话、检查点、模型、调用记录和设置我都要事务。SQLAlchemy 管表结构和迁移，aiosqlite 让写入留在同一个事件循环。 |
| cryptography | 我用它生成本地 CA 的密钥和证书，并判断信任状态。代理只终结 Cursor 域名的 TLS，我不引入完整的中间人代理框架。 |
| Node.js 22 | 前端和桌面壳都放在 Node.js 里。界面不使用 PySide6，避免再维护一套 Qt 界面。 |
| Electron | 我需要主窗口、托盘、系统对话框，并由桌面进程拉起 Python 服务。Electron 的主进程就是 Node.js，能完成这些系统能力。 |
| Vite、React、TypeScript | 控制台是表格、表单和图表。Vite 负责本地开发与构建，React 负责页面状态，TypeScript 约束控制 API 的类型。界面只调用回环地址上的控制接口，不接触 Cursor 协议。 |
| i18next、ECharts | 文案我支持简体中文、英文和葡萄牙语。用量和延迟图用 ECharts。明暗主题用前端样式切换。 |
| tree-sitter Python 绑定 | 本地代码搜索我按语法切块，词项放在 SQLite。网页搜索用 httpx 调我配置的接口。 |
| 协议提取工具 | 我从 Cursor 产物里解析服务和消息定义，生成 `.proto` 或 Python 消息类。Cursor 协议会变，没有这套工具我无法持续对齐字段。 |
| 协议抓包调试服务 | 我拦截并解码 Cursor 请求，落到本地库，再开调试页对照上下行。用来验证本机实现与真实流量是否一致。 |

## 我采用的设计模式

- **端口与适配器。** 我的会话运行时只认识统一的模型事件和工具结果。Cursor 编解码、三种上游协议和 SQLite 都放在端口外。两边的字段会分别变化，核心循环不能依赖任何一边的报文。
- **策略。** Chat Completions、Responses、Anthropic 我做成同一个流式调用接口，按模型配置选择。三种请求体和用量字段不同，运行时只消费一种事件。
- **状态机。** run 我只设进行中、收尾、结束。插入、打断、取消和重复命令先看状态再执行。这些命令会并发到达，散落的条件判断会造成两个当前 run。
- **注册表。** `request_id` 我对应一条传输，`conversation_id` 我对应一个会话。Cursor 的上下行不是同一个 HTTP 请求，后续包要送回原来的通道。
- **仓储。** 每类持久化数据我设一个仓储，由一个工作单元提交事务。检查点、消息和工具轮次要一起成功。
- **空对象。** 遥测接口我返回固定的空成功响应。Cursor 会调用它们，我不采集、不上报。
- **外观。** 官方回退我收口成一个转发器，负责地址、认证头和按路径放行。Tab 与未知 RPC 的规则集中在一处。

## 我的界面边界

桌面是 Node.js 应用。Electron 主进程负责窗口、托盘和拉起 Python 服务；渲染进程只通过回环地址上的控制接口访问服务。界面里没有广告、插件页，也没有外部文档或发布源入口。
