设计思路

原则很短；细节见 Markdown。代码里已落地的模式如下。

端口与适配器

runtime/ports/* ← adapters/* 实现。会话核心不 import protobuf / httpx / SQLAlchemy。

策略：上游协议

ProviderRouter 按 provider_type 选 Chat / Responses / Anthropic，统一 ModelPort.stream。

外观：本机接入

LocalAccessFacade 收口 CA、代理启停、写 Cursor settings.json。

空对象：遥测

NullTelemetry + 固定 IsConnected，不采集不上报。

分流：本地 vs 官方

routing.py 的 LOCAL_PATHS / TAB_PATHS；Tab 永不本地实现。

装配：AppServices

build_services() 一次接线；lifespan 停代理、dispose engine。

完整叙述：design.md · 模块边界：modules.md · Agent 下行现为 AgentServerMessage protobuf（对照 byok）；工具主路径为 Cursor client-exec。

数据与控制流

三条主路径，箭头上的名字均为代码中的符号或路径。

流程 A — 桌面启动 → 控制面就绪

Electron
ensureBackend() → GET /healthz 失败则 spawn python -m cursor_switch.control.main 或 resources/.../cursor-switch-server
FastAPI
lifespan → build_services() → init_schema → AppServices 就绪
Renderer
api/client.ts → /api/models · /api/overview · /api/harness/...

流程 B — 开启接管（Harness）

1. UICursorGates / CursorSettingsPage
PUT /api/harness/cursor/enabled
2. HarnessServiceapp/harness.py
读 ports → facade
3. LocalAccessFacadeset_enabled(True)
proxy.start(8788)
4. cursor_settings写 http.proxy
http.proxySupport=on
5. Cursor完全退出重启
流量进 MITM

关闭接管：停代理 + 清掉 PROXY_KEYS。CA 初始化：POST /api/harness/cursor/ca/initialize → CaManager → ~/.cursor-switch/ca/ca.crt。

Cursor
HTTPS *.cursor.sh → CursorProxy :8788
routing.py

cursor/routes

runtime
compile / session → ModelPort.stream → ProviderRouter → 上游 SSE
回写
envelope / transport → SSE / WS 下行 → on_call_finished → calls 表

流程 D — 模型目录合并

AvailableModels / GetUsableModels → ModelCatalog → 带 UPSTREAM_URL_HEADER 拉官方目录 → append 本地 models（不替换）

持久化

定义：adapters/persistence/models.py · 引擎：db.py · 默认 URL：sqlite+aiosqlite:///~/.cursor-switch/cursor-switch.db

models

  • context/max_output, enabled, sort_order
  • extra_json, headers_json, group_name

calls

CallRow
  • model_id, status, 时延字段
  • input/output/cache tokens

settings

  • ports, proxy, desktop, tab
