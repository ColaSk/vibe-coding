# AGENTS.md — littleagent

本文件是 littleagent 的硬约束，与代码同等权重。动手前读完，动手后按「提交前检查」自查。

配套文档：`docs/architecture.md`（架构）、`docs/python-environment.md`（Python 解释器/环境/依赖的权威规则）、`docs/roadmap.md`（阶段与出口条件）。

## 项目定位

一个进程内、async-first、协议驱动的极简 Agent 框架。库，不是运行时。

做：多步推理循环、模型抽象、工具抽象、记忆投影、可插拔动作范式、流式与可观测。

不做：常驻服务、多租户、审批流、渠道接入、持久会话库、可视化平台。这些属于运行时的问题域，一旦出现在需求里，先讨论边界，不要直接实现。

## 分层与依赖方向

四层，依赖严格单向向下。由 `import-linter` 机检，不靠人守。

- **L0 契约** `contracts/`：数据形状与错误类型。不 import 包内任何其它模块。
- **L1 能力** `model/` `tool/` `memory/` `action/` `observe/` `prompt.py`：只能 import L0。**L1 内部各模块互不 import**（`model/` 不认识 `tool/`）。
- **L2 编排** `agent.py`：只依赖 L0 与 L1 暴露的协议，不依赖任何具体实现类。
- **L3 表面** `cli.py`：可依赖以上任意层。

`src/littleagent/__init__.py` 是唯一的 re-export 点，也是唯一的公开 API 面。子模块路径不是公开契约，随时可重排。

## 十条硬规则

1. **分层**：依赖方向如上。违反即 `make check` 红，不接受「先这样后面再拆」。
2. **规模预算**：单文件 ≤300 行。Phase 1 生产代码总量 ≤1500 行。新增文件必须立刻抵租——减少调用路径、减少概念或消除重复逻辑——否则并入既有模块。
3. **类型**：全量注解，`mypy --strict` 全绿。禁裸 `Any`（外部边界用 pydantic 模型或 `object` + 显式收窄）。抽象优先 `Protocol` 而非 ABC。只用现代语法：PEP 695 的 `type` 与泛型参数、`X | None`、`Self`、`@override`；禁 `typing.List/Dict/Optional/Union`，不为旧 Python 留兼容分支。
4. **状态表达**：分支基于封闭联合与具名错误类。禁 freeform 字符串分支，禁语义哨兵（用 `0`、空字符串、空字典表达「没有」或「失败」）。让不可能的状态无法被表达出来。
5. **异步纪律**：核心路径全 async。禁在 async 函数里做阻塞 IO 或 CPU 长任务（需要就 `asyncio.to_thread`，并写明理由）。`asyncio.run` 全仓库只允许出现一次，在同步入口包装处。
6. **依赖预算**：核心运行时依赖 ≤3 个，当前是 `httpx` + `pydantic`。其余一律 extras。日志不引渲染库，prompt 不引模板引擎——prompt 是类型化构造函数，能被类型检查。依赖只在 `pyproject.toml` 声明——运行时依赖进 `[project].dependencies`，开发工具进 `[dependency-groups].dev`（放 extras 会泄漏给使用者），可选能力进 `[project.optional-dependencies]`。新增时先写声明再安装；禁 `conda install` Python 包，禁 `pip install` 未声明的包，禁叠第三方项目管理器。完整规则见 `docs/python-environment.md`。
7. **测试边界**：每个 L1 模块有边界测试。模型替身只用 `tests/fakes.py` 的脚本化 `FakeModel`，禁 mock 内部实现细节（那只是在测 mock）。故障要注入：模型报错、工具报错、参数不合法、取消、步数耗尽。修 bug 先写能失败的回归测试。
8. **无兼容层**：项目未发布，没有兼容义务。不留别名、shim、fallback、废弃路径、「以防万一」的分支。重构就是删掉旧路径。
9. **命名**：导出符号 2-3 个词且全仓库唯一，禁 `get`/`run`/`handle` 这类单词导出。禁新建 `utils/` `helpers/` `common/`，模块按概念命名。一个概念全仓库一种拼写。
10. **注释**：只写代码本身表达不了的东西——不变量、生命周期顺序、所有权边界、故意的取舍。不写语法旁白，不写变更历史。

## 不变量

违反其中任何一条都是缺陷，不是风格问题。

- **每个动作恰好一条记录**。每个动作步无论成功、失败还是被取消，都产生且仅产生一个 `ActionStep`。不存在「静默什么都没发生」的路径。
- **默认值不吞合法值**。禁 `x or default` 这种取默认值写法，它会把 `0`、`""`、空容器当成「未传」。用 `None` 做哨兵显式区分。`max_steps=0` 必须报错，绝不静默变成默认值。
- **事实记录在其发生之处**。任务附件属于 `TaskStep`，工具产物属于产生它的那个 `ActionStep`。禁把同一批数据重复注入每一步——上下文会线性膨胀。
- **取消贯穿全链路**。取消走 asyncio 原生取消，模型请求与工具执行都在可取消范围内。「在下一步开头检查一个布尔标志」不算实现了取消，长工具调用会停不下来。
- **超时即取消，不承诺硬杀**。超时语义是「已请求取消」，外部进程可能仍在运行，这一点必须在文档和错误信息里写明，不许暗示更强的保证。
- **计量在记录处收口**。token 与耗时由步骤记录的构造过程统一收集，不靠按步骤类型挂回调——那样新增步骤类型就会静默漏掉统计。
- **序列化从字段派生**。结果与步骤的导出由 dataclass 字段生成，配 round-trip 测试。禁手写导出字典，那必然随字段增加而漏项。
- **结束只走一条路**。循环结束只能通过 `Finish` 结果，不用异常做控制流。
- **声明的检查必须真的被调用**。写了校验函数却没接进调用链，等于文档说谎。lint 拦未被引用的私有函数。
- **代码执行不是安全边界**。若将来引入代码执行能力，本地执行器永不宣称隔离；需要隔离就用进程或容器边界，并在文档里写清威胁模型。

## 工作流程

契约优先，一次一层：

1. 先在 `contracts/` 落数据形状与错误类型。
2. 再写测试，表达期望行为与失败路径。
3. 最后写实现。
4. `make check` 全绿才算完成。

不要在一个改动里同时新增契约、实现和表面。每个改动应当能用一句话说清它保护了什么行为。

## 命令

```bash
conda activate littleagent
make check    # format 检查 + lint + mypy --strict + 分层检查 + 测试
make test     # 只跑测试
make fmt      # 就地格式化
```

`make check` 是唯一入口，人和 AI 用同一条命令。不要绕过它单跑某个工具就宣称完成。

## 提交前检查

- `make check` 全绿。
- 新增或修改的行为有对应测试，且该测试在改动前会失败。
- 没有新增未使用的导出、参数、分支或文件。
- 生产代码行数变化能被一句话解释清楚：新增了什么能力，或者划清了什么边界。
- 若改动触及上面任何一条不变量，在提交信息里写明它如何仍然成立。
